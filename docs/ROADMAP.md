## 🏛️ 1. الفلسفة والمبادئ المعمارية (Core Philosophy)

تعتمد بنية **AppImage Studio** على 4 ركائز أساسية:

1. **الاستقلالية التامة (Zero External Dependencies):**  
   التطبيق الناتج وتطبيقنا نفسه قائمان بذاتهما 100% دون طلب تثبيت مكتبات عبر سطر الأوامر (`apt`, `dnf`, `pacman`).
2. **بساطة الواجهة وسلاسة الاستخدام (Frictionless UX):**  
   تمكين أي مبرمج أو مستخدم من إنشاء حزمته خلال أقل من دقيقة.
3. **التوافقية العابرة للتوزيعات (Cross-Distro Compatibility):**  
   ضمان عمل الحزم المولدة عبر مختلف توزيعات لينكس (Ubuntu, Debian, Fedora, Arch, Mint, openSUSE).
4. **دعم بيئات خطوط الإنتاج وأتمتة المطور (CI/CD Ready):**  
   جاهزية التحزيم عبر خطوط الإنتاج والـ GitHub Actions والسيرفرات المعزولة.

## 🎯 2. الجمهور المستهدف وحالات الاستخدام (Target Audience)

* **مستخدمو لينكس وعشاق البرامج المحمولة (Linux Users & Power Users):** تحويل مجلدات البرامج المحمولة (`.tar.gz` / `.zip` مثل Blender, Telegram, VS Code, ألعاب مستقلة) إلى ملف تنفيذي واحد ودمجها فوراً في قائمة "ابدأ" والتطبيقات دون الحاجة لكتابة أوامر أو ملفات `.desktop`.
* **مطورو Flutter و Desktop على لينكس:** تغليف التطبيقات بنقرة زر واحدة دون الحاجة لكتابة ملفات `.desktop` و `AppRun` يدوياً.
* **مطورو اللغات الحديثة (Rust, Go, C++, Python):** تجميع وحزم الملفات التنفيذية مع مكتباتها المرتبطة (`.so`).
* **مطورو الألعاب ومحركات الألعاب (Godot, Raylib, إلخ):** إنتاج نسخة موحدة وجاهزة للتشغيل الفوري للاعبين.
* **المطورون المستقلون (Indie Developers):** توزيع برامجهم مباشرة عبر موقعهم أو GitHub دون انتظار موافقة المتاجر.

## ⚙️ 3. آلية العمل والتغليف الذاتي (Self-Containment Workflow)

```
┌─────────────────────────────────────────────────────────────┐
│ 1. اختيار مجلد البرنامج (مثال: bundle الخاص بفلاتر أو bin)    │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. إنشاء هيكل AppDir الذاتي:                                │
│    ├── AppRun (سكربت ذكي يضبط مسارات المكتبات LD_LIBRARY_PATH)│
│    ├── [AppName].desktop (ملف تعريف النظام والتصنيف)         │
│    ├── [icon].png + .DirIcon (أيقونة التطبيق المعتمدة)       │
│    └── usr/ أو bundle/ (كامل الملفات والمكتبات المشتركة .so) │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. أداة الضغط والتوليد (appimagetool):                       │
│    - فحص الأداة المدمجة أو تنزيلها تلقائياً بالخلفية.        │
│    - ضغط الحزمة بصيغة SquashFS/ISO مع تعيين أذونات التنفيذ. │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 4. الناتج النهائي: [AppName]-x86_64.AppImage                 │
│    - ملف تنفيذي مستقل يعمل على مختلف توزيعات لينكس!        │
└─────────────────────────────────────────────────────────────┘
```

## 🧰 4. مصفوفة الميزات والقدرات (Feature Matrix)

### 🔹 الميزات الحالية المكتملة (v1.0.0):
* [x] **محرك التحزيم والتوليد الأساسي:** إنشاء هيكل `AppDir` وسكربت `AppRun` الذكي تلقائياً.
* [x] **الكشف الذكي التلقائي (Smart Auto-Detection):** التعرف على اسم التطبيق، الملف التنفيذي الرئيسي، والأيقونات.
* [x] **محرر البيانات الوصفية (Metadata Editor):** تعديل الاسم، الوصف، الإصدار، والتصنيفات القياسية.
* [x] **استقلالية كاملة وبدون إنترنت (Offline-First):** فحص وتضمين أداة `appimagetool` محلياً.
* [x] **نافذة سجل البناء الحية (Live Build Console):** متابعة فورية للمخرجات وتشخيص الأخطاء بالألوان.
* [x] **تكامل اختياري مع سطح المكتب (Desktop Integration):** إمكانية تثبيت التطبيق المولد مباشرة في قائمة "ابدأ" وشريط المهام.
* [x] **زر التجربة والتشغيل المباشر (Test Run):** تشغيل واختبار الـ AppImage المولد فوراً.
* [x] **دعم كامل للغتين (Arabic & English):** واجهة متكيفة تلقائياً مع لغة النظام مع دعم كامل للـ RTL/LTR وزر تبديل فوري.
* [x] **أتمتة البناء والنشر عبر GitHub Actions:** توفير Workflow لتوليد الحزم تلقائياً عند كل إصدار.
