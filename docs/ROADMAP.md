## 🏛️ 1. الفلسفة والمبادئ المعمارية (Core Philosophy)

تعتمد بنية **AppImage Studio** على 4 ركائز أساسية:

1. **الاستقلالية التامة (Zero External Dependencies):**  
   التطبيق الناتج وتطبيقنا نفسه قائمان بذاتهما 100% دون طلب تثبيت مكتبات عبر سطر الأوامر (`apt`, `dnf`, `pacman`).
2. **بساطة الواجهة وسلاسة الاستخدام (Frictionless UX):**  
   تمكين أي مبرمج أو مستخدم من إنشاء حزمته خلال أقل من دقيقة.
3. **التوافقية العابرة للتوزيعات (Cross-Distro Compatibility):**  
   ضمان عمل الحزم المولدة عبر مختلف توزيعات لينكس (Ubuntu, Debian, Fedora, Arch, Mint, openSUSE).
4. **دعم بيئات خطوط الإنتاج وأتمتة المطور (CI/CD & CLI Ready):**  
   جاهزية التحزيم المؤتمت عبر واجهة سطر الأوامر (Headless CLI) وسكربتات البناء الطرفية لبيئات السيرفرات المعزولة.

## 🎯 2. الجمهور المستهدف وحالات الاستخدام (Target Audience)

* **مستخدمو لينكس وعشاق البرامج المحمولة (Linux Users & Power Users):** تحويل مجلدات البرامج المحمولة (`.tar.gz` / `.zip` مثل Blender, Telegram, VS Code, ألعاب مستقلة) إلى ملف تنفيذي واحد ودمجها فوراً في قائمة "ابدأ" والتطبيقات دون الحاجة لكتابة أوامر أو ملفات `.desktop`.
* **مطورو Flutter و Desktop على لينكس:** تغليف التطبيقات بنقرة زر واحدة دون الحاجة لكتابة ملفات `.desktop` و `AppRun` يدوياً.
* **مطورو اللغات الحديثة (Rust, Go, C++, Python):** تجميع وحزم الملفات التنفيذية مع مكتباتها المرتبطة (`.so`).
* **مطورو الألعاب ومحركات الألعاب (Godot, Raylib, إلخ):** إنتاج نسخة موحدة وجاهزة للتشغيل الفوري للاعبين.
* **المطورون المستقلون (Indie Developers):** توزيع برامجهم مباشرة عبر موقعهم أو GitHub دون انتظار موافقة المتاجر.

## ⚙️ 3. آلية العمل والتغليف الذاتي (Self-Containment Workflow)

```
┌─────────────────────────────────────────────────────────────┐
│ 1. اختيار مجلد البرنامج (مثال: bundle الخاص بفلاتر أو bin)    │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. إنشاء هيكل AppDir الذاتي:                                │
│    ├── AppRun (سكربت ذكي يضبط مسارات المكتبات LD_LIBRARY_PATH)│
│    ├── [AppName].desktop (ملف تعريف النظام والتصنيف)         │
│    ├── [icon].png + .DirIcon (أيقونة التطبيق المعتمدة)       │
│    └── usr/ أو bundle/ (كامل الملفات والمكتبات المشتركة .so) │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. أداة الضغط والتوليد (appimagetool):                       │
│    - فحص الأداة المدمجة أو تنزيلها تلقائياً بالخلفية.        │
│    - ضغط الحزمة بصيغة SquashFS/ISO مع تعيين أذونات التنفيذ. │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 4. الناتج النهائي: [AppName]-[Version].AppImage              │
│    - ملف تنفيذي مستقل يعمل على مختلف توزيعات لينكس!        │
└─────────────────────────────────────────────────────────────┘
```

### 🔵 المرحلة الثانية: v1.2.0 — كفاءة المحرك، إدارة التكامل، وفحص التبعيات (أولوية عالية جداً ⭐⭐⭐⭐⭐)
> **الهدف:** رفع جودة وتوافقية الحزم المولدة عبر التوزيعات، وتوفير تحكم متقدم في بيئة التشغيل وإدارة تطبيقات AppImage المثبتة على النظام.

- [ ] 🔗 **نسخ الروابط الرمزية الآمن وتقرير كفاءة الضغط (Symlink-Safe Bundling & Size Report):**
  - الحفاظ على الروابط الرمزية (`Symlinks`) لمكتبات `.so` أثناء نسخ الحزمة لمنع تضخم الحجم أو تلف المكتبات.
  - عرض إحصائية مقارنة بعد البناء: (حجم المجلد الأصلي $\leftarrow$ حجم الـ AppImage النهائي ونسبة التوفير المئوية %).
- [ ] 🎯 **تحسين تكامل سطح المكتب والشريط السفلي (`StartupWMClass` & `MimeType`):**
  - تضمين `StartupWMClass` تلقائياً في ملفات `.desktop` لضمان ظهور أيقونة التطبيق الحقيقية في شريط المهام (Dock) على بيئات KDE Plasma و GNOME.
  - دعم تحديد أنواع وامتدادات الملفات (`MimeType`) التي يمكن فتحها بواسطة التطبيق.
- [ ] ⚙️ **إعدادات التشغيل المتقدمة داخل `AppRun` (Advanced Launch Options):**
  - قسم خيارات متقدمة قابل للطي يتيح:
    - تشغيل التطبيق في وضع الطرفية (`Terminal=true`) للأدوات النصية.
    - تمرير معاملات تشغيل افتراضية (`CLI Arguments` مثل `--no-sandbox` لتطبيقات Electron).
    - حقن متغيرات بيئة مخصصة (`Environment Variables` مثل `GDK_BACKEND=x11`).
- [ ] 🗜️ **التحكم في محرك الضغط وفلترة الملفات الزائدة (Compression Engine & Ignore Filters):**
  - اختيار خوارزمية الضغط (`zstd` للسرعة الفائقة، أو `xz` لأصغر حجم ممكن عند النشر).
  - استثناء المجلدات والملفات غير الضرورية تلقائياً (مثل `.git`, `.DS_Store`, `CMakeFiles`, `__pycache__`) لتقليص حجم الحزمة.
- [ ] 🗂️ **مدير تطبيقات AppImage المثبتة (Installed AppImages Manager & Uninstaller):**
  - نافذة لإدارة كافة تطبيقات AppImage المدمجة في قائمة النظام (`~/.local/share/applications/`).
  - اكتشاف وتنظيف الاختصارات التالفة/اليتيمة (التي حُذف ملف الـ AppImage الخاص بها)، أو إلغاء تثبيت أي تطبيق بنقرة زر، أو تثبيت ملف `.AppImage` خارجي مباشرة في قائمة النظام.
- [ ] 🔍 **فاحص وحازم التبعيات الذكي مع توافقية GLIBC (`ldd` & `GLIBC` Inspector):**
  - فحص الملف التنفيذي عبر `ldd` لعرض المكتبات المشتركة المطلوبة (`.so`) مع استثناء مكتبات النواة الأساسية (`AppImage excludelist`).
  - خيار لتضمين مكتبات الطرف الثالث المفقودة تلقائياً داخل `lib/`، مع عرض الحد الأدنى المطلوب من `GLIBC` وأقدم توزيعة مدعومة.
- [ ] 🔄 **توليد بيانات AppStream التلقائي والتحديثات الذكية عبر Zsync (`metainfo.xml` & `AppImageUpdate`):**
  - توليد ملف `usr/share/metainfo/[app].appdata.xml` تلقائياً لإنهاء تحذير `AppStream upstream metadata is missing` في سجل البناء والتوافق التام مع معايير Freedesktop و AppImageHub.
  - دعم تضمين رابط التحديث التلقائي (`Zsync Update Information`) لمستودعات GitHub Releases لتوليد ملفات `.zsync` ودعم التحديثات التفاضلية (Delta Updates).
